- **Real bug found and fixed during agent-browser verification**: the first ingestion produced a model where Exploded View barely changed the shape. Root cause: `stlAssembly.ts` set every node's mesh geometry directly from each STL's raw (shared-coordinate-system) vertices without ever setting `node.setTranslation(...)` — so every node's local position defaulted to `(0,0,0)`. The explode logic (`useModeEffects` in `Viewer3D.tsx`) offsets each node based on `(node.position - sceneCenter)`, so with all nodes at the same local `(0,0,0)`, every part got an *identical* offset — the whole assembly translated uniformly instead of separating. Fixed by re-centering each part's geometry on its own vertex centroid in `stlAssembly.ts` and moving that centroid into `node.setTranslation([cx,cy,cz])` — this preserves the assembled (non-exploded) pose exactly while giving each part a distinct position to explode from.
- Also bumped `GltfModel`'s explode factor from the shared default (1.6) to 2.6 in `Viewer3D.tsx` — with a real kit, a few large parts dominate the bounding box, so parts nearer the shared center need a stronger multiplier to visibly separate at the same zoom level.
